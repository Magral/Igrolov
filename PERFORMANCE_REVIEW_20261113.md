# Подготовка оптимизаций после 1.12.0

Основание: подборка от 13 ноября в чате «Еженедельный поиск материалов».
Проверено по исходникам `cf6dcda` (версия приложения 1.12.0).

## Подготовленный код

- `SteamArtworkImage.kt`: один запомненный `ImageRequest` на текущий URL и заголовки вместо создания запроса при каждой рекомпозиции.
- Состояние обложки и область её резервных загрузок привязаны к `(url, appId)`. При переиспользовании позиции списка для другой игры предыдущие задачи и задержанные повторы отменяются.
- Блокирующие резервные загрузки выполняются через `runInterruptible(Dispatchers.IO)`. Это передаёт прерывание поддерживающему его блокирующему коду. Само по себе прерывание потока не гарантирует немедленного закрытия HTTP-сокета; существующие сетевые тайм-ауты остаются необходимы.
- Компонент выделен из `MainActivity` для проверки восстановления после ошибки и отмены без обращения к живым CDN.
- Добавлены два UI-сценария: отсутствующее изображение → успешный резерв; смена игры при заблокированном резерве → отмена старой задачи и загрузка новой обложки.
- Workflow запускается также для pull request; публикация остаётся доступна только для release-коммита в main после всех проверок.

Замер ускорения или снижения трафика ещё не выполнен. Эти изменения не следует описывать как доказанное ускорение на определённый процент.

## Применимость остальных рекомендаций

| Направление | Найдено в 1.12.0 | Следующая работа и критерий |
| --- | --- | --- |
| Flow и рекомпозиции | В `MainActivity` нет `collectAsState`; используются Compose state и наблюдение WorkManager через LiveData. Общий таймер цен уже ограничен видимыми вкладками и RESUMED. | Измерить рекомпозиции списка при обновлении одной цены; выносить чтение состояния в карточки только по результатам измерения. Не добавлять Flow ради самого перехода. |
| Coil | Установлен 3.0.4. Объединение сетевых запросов `DeDupeConcurrentRequestStrategy`, появившееся позже, здесь не включено. | Отдельная миграция зависимостей. Новые Coil требуют обновлений Kotlin/SDK/Compose; текущие Kotlin 2.0.21 и compileSdk 35 нельзя игнорировать. Проверить Gradle metadata и разрешённое дерево зависимостей до выбора версии. |
| Отмена | Поиск цен уже имеет координатор с дедлайном, отменой Future и отсечением поздних результатов. Worker уже использует `runInterruptible`. В резерве обложек этого не было. | После текущей правки проверить долгий реальный HTTP-ответ и закрытие соединения; продолжить точечный аудит широких catch/runCatching в цепочках отменяемых задач. |
| Кэш ошибок | В подборке упомянут Coil 3.5.0: обновление просроченных сохранённых HTTP-ошибок. | Проверка именно HTTP 404 → истечение срока кэша → HTTP 200 с тем же URL после миграции. Текущий новый тест проверяет резерв после отсутствующего файла, а не HTTP-кэш. |
| Сеть и память | Общая загрузка цен и обложек использует разные механизмы. | Сравнить холодную/повторную прокрутку одного фиксированного списка: число запросов, байты, источники изображений, пропущенные кадры и пик памяти; отдельно смену вкладок и фон. Не считать весь UID-трафик трафиком только обложек. |

## Проверки перед включением

- Unit-тесты, сборка приложения и пакета instrumentation.
- Полный прогон Android 26/29 с новыми сценариями обложек.
- Фоновый мониторинг Android 34 и прежние проверки цен/изданий.
- Живые проверки вертикальных обложек; отсутствие подмены вертикали горизонтальной картинкой.
- Для будущей миграции Coil дополнительно: параллельные одинаковые запросы с отменой одного потребителя, HTTP 404 → 200, память после ухода в фон.
