# Исследование Digiseller API для 1.0.4

Официальная документация: https://my.digiseller.com/inside/api_catgoods.asp и https://api.digiseller.com/swagger/ui/index

## Подтверждено документацией
- `GET /api/categories?seller_id={seller_id}` выдаёт дерево категорий **конкретного продавца**.
- `GET /api/shop/products?seller_id={seller_id}&category_id={category_id}` выдаёт товары категории **конкретного продавца**.
- `GET /api/products/{product_id}/data` возвращает `product.category_id` и `product.breadcrumbs` **при передаче seller_id** (в текущем запросе приложения seller_id отсутствует).
- Описанные в API поля `collection` и `type` означают тип содержимого/доставки, **не** тип Steam Gift или Steam Key.

## Не подтверждено
- Параметр категории в глобальном `GET /api/products/search2` для фильтрации Gift/Key. Нельзя добавлять `category_id` к `search2` без проверки его фактической поддержки.
- Единая глобальная классификация всех продавцов на Gift/Key/аккаунты: seller category ID может быть уникальным для магазина.

## Вывод для реализации
Не следует выдавать категории продавца за общую классификацию Steam. Без надёжного определения продавца и семантики категории серверный фильтр может удалить корректные предложения. Следующий этап — исследовать структуру реальных ответов `search2`, определить seller_id и проверить применимость category breadcrumbs для нескольких продавцов. До этого сохранить клиентский фильтр и не утверждать, что серверная фильтрация реализована.
