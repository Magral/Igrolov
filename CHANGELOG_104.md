# Игролов 1.0.4 — изменения (кандидат)

- Повторные попытки запросов поиска и мониторинга при временных сетевых ошибках (до 2 повторов).
- Защита интерфейса от результатов устаревшего поиска.
- Ограничение параллельных запросов карточек товаров четырьмя потоками.
- Показ результатов поиска порциями по 30 карточек с кнопкой «Показать ещё».
- Кэширование фильтрации результатов на время неизменных параметров.
- Для мониторинга цены и уведомлений проверяется доступность не более 5 наиболее дешёвых подходящих предложений через Digiseller product data API; неподтверждённые предложения не запускают уведомления.
- Обновлены версия приложения и текст интерфейса.

## Ограничения

- Не подтверждена финальная сборка и работа на устройстве после всех коммитов.
- Проверка доступности через поле is_available не гарантирует доступность выбранного варианта, региона и итоговую цену на странице продавца.
- Серверная фильтрация по категориям Digiseller не включена без проверки документированных параметров API.
- Ветка stable/v1.0.3 хранит исходную рабочую базу для отката.

## Подпись отладочных сборок

- Начиная с коммита `f69b454`, GitHub Actions восстанавливает один и тот же **тестовый** JKS из `signing/igrolov-debug.jks.base64`, затем Gradle подписывает им Debug APK.
- Ключ намеренно хранится в исходниках и поэтому **не является секретом**. Не использовать его для production/Play Store или хранения доверенных данных.
- APK, установленные до этой смены подписи, **не смогут обновиться** поверх старой установки; для перехода на закреплённую подпись потребуется однократная переустановка. Последующие Debug APK с тем же applicationId, ключом и возрастающим versionCode смогут обновляться без удаления.
- Переход на пользовательский release-ключ в будущем снова потребует миграции подписи или отдельного package name.

- Поиск каталога теперь выполняется в отдельном однопоточном исполнителе. Устаревшие запросы прекращаются между страницами; после закрытия Activity исполнитель останавливается.
