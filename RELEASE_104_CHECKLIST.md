## Диагностика схемы категорий (коммит 594ad2e)
- Добавлено безопасное логирование **только имён** полей первого товара `search2`, содержащих `categor`, `seller`, `owner`, `platform`; без значений, ID, запросов и названий товаров.
- Это исследовательский шаг, **не реализация фильтра категорий**. Если API не возвращает такие поля, журнал покажет пустой список.
- Для проверки: запустить поиск на устройстве и посмотреть Logcat с фильтром `IgrolovCatalog`; сопоставить полученные ключи с документированными схемами Digiseller.
- После подтверждения структуры ответа реализовать проверяемую классификацию и удалить диагностическое логирование перед выпуском.

## Защита региональных цен (коммит 039ff1e)
- Мониторинг не считает цену каталога подтверждённой, если в карточке Digiseller найден выбор страны/региона: базовая цена может относиться к другому варианту.
- Это **консервативное временное правило**: реальные предложения с выбором региона могут не вызвать уведомление даже при доступной РФ. Для полноценной поддержки требуется отдельный расчёт цены выбранного варианта и проверка доступности.
- Ручной поиск продолжает показывать такие предложения для самостоятельной проверки.
- Требуется подтвердить успешную сборку и поведение на устройстве. Не закрывать пункт региональных цен до реализации точной проверки вариантов.

## Покрытие категорий в ответах search2 (коммит 24f5bcc)
- Диагностика расширена с первого товара на **все товары первой страницы**: фиксируются только имена подходящих полей, количество товаров с полями категории/продавца и общее количество, без значений, ID, названий или текста запроса.
- Причина: структура ответа может различаться по продавцам; отсутствие категории у первого товара не доказывает отсутствие категорий у остальных.
- Для подтверждения классификации всё ещё нужны реальные данные о **значениях** категорий и соответствии типам Gift/Key/аккаунт. Текущая диагностика сама по себе этого не подтверждает.
- После успешной сборки выполнить несколько поисков и посмотреть `IgrolovCatalog` в Logcat; если поля отсутствуют, перейти к анализу карточек товаров и справочника площадок, а не выдумывать серверный фильтр.

## Исправление фильтра региона в ручном поиске (коммиты cc04ab0, 11714aa)
- Устранена ошибка: параметр `allowUnconfirmed` в `OfferRules.eligible` существовал, но игнорировался, из-за чего ручной поиск скрывал предложения с неподтверждённым регионом.
- Теперь ручной поиск явно использует `allowUnconfirmed = true`: неизвестный регион виден для самостоятельной проверки, а явно исключённая РФ не показывается.
- Мониторинг продолжает вызывать `allowUnconfirmed = false`: предложения без подтверждения РФ по названию не становятся основанием для уведомлений.
- Требуется проверить на устройстве все три состояния: «РФ указана в названии», «РФ исключена», «Регион РФ не подтвержден». Это исправление **не подтверждает** фактическую доставку в РФ.

## Защита мониторинга от неопределённого типа доставки (коммит ead2855)
- В ручном поиске остаются предложения с типом `Не указан` для проверки пользователем.
- Автоматический мониторинг теперь рассматривает только явно распознанные `Gift` или `Key`, даже если пользователь выбрал фильтр `Все`.
- Смешанные заголовки Gift+Key и заголовки без однозначного способа передачи не становятся источником уведомлений о цене.
- Это не замена классификации по реальным метаданным API: названия продавцов могут быть неточными. Нужны тесты на устройстве и проверка API.

## Проверка актуальной цены перед уведомлением (коммит fd5bf8d)
- Мониторинг теперь сверяет рублёвую цену каталога с `product.prices.default.RUB` из свежей карточки Digiseller (допуск 1 копейка), дополнительно к `is_available` и отсутствию выбора региона.
- При отсутствии числовой цены RUB, несовпадении или сетевой ошибке предложение не подтверждается для автоматического уведомления. Это защищает от устаревшей цены каталога, но может давать пропуски при расхождении форматов/цен API.
- **Не подтверждает итоговую цену оформления покупки** (комиссии, дополнительные параметры, валюта и ограничения). Требуются реальные тесты и проверка API; пункт региональной цены остаётся открытым.

## Клиентское сопоставление seller_id/category_id (коммиты f151c4f, d0c04cb)
- Добавлен `SellerCategoryResolver.kt`: при ручном поиске для **первых 12 самых дешёвых предложений** выполняет запрос карточки с `seller_id`, а при ненулевом `category_id` — запрос категорий **этого же продавца** с кешированием по продавцу.
- Только явно названные категории Gift/Gifts/Гифт или Key/Keys/Ключ могут уточнить тип; категория аккаунтов/аренды исключает товар из ручной выдачи. Категории «Steam», «Игры» и отсутствие категории не меняют тип и не исключают товар.
- Если заголовок противоречит категории, тип становится `Не указан` (не угадываем способ передачи). Сбой API не удаляет предложение.
- Это **не серверный фильтр**: категории магазинов локальны для продавца, `search2` не возвращает category_id. Остальные предложения (после первых 12) продолжают классифицироваться по названию.
- Необходимы CI-компиляция и проверка на устройстве; не отмечать категоризацию как завершённую до этих проверок. Мониторинг на этом шаге не менялся.

## Автоматизация CI (20.10.2026)
- Android workflow запускается на каждом push в main, вручную и ежедневно в 05:37 UTC. Проверяет версию 1.0.4, debug-подпись, JVM unit tests и собирает debug APK. Загружает APK (90 дней) и отчёты тестов (30 дней). Повторные push отменяют устаревшие запуски в одной ветке.
- Digiseller Probe запускается при изменениях скрипта/валидатора/workflow, вручную и ежедневно в 04:17 UTC. Сначала выполняет offline-тесты валидатора, затем реальные запросы Digiseller, проверяет JSON-отчёт и пишет GitHub Actions Step Summary (Gift/Key/Excluded/Unknown, ошибки API). Артефакт хранится 30 дней.
- CI **не заменяет** тесты на физическом устройстве, проверку актуальной цены/региона и production-подпись. Успех новых расписаний и результатов на момент настройки ещё не подтверждён.
- Workflow GitHub Actions запускаются по расписанию с возможной задержкой; требуется включённый Actions для репозитория.

## Уточнение процесса разработки
- По запросу владельца ежедневные cron-запуски Android и Digiseller отменены: CI запускается на push и вручную.
- Рабочий цикл помощника: изменить код → проверить GitHub Actions, журналы и артефакты самостоятельно → исправить ошибки → продолжить следующий пункт чек-листа. Не требовать от владельца ссылок на сборки или ручного подтверждения успеха.
- Проверка CI и работа над задачами происходят во время активной сессии разработки; GitHub Actions сами по себе не запускают новые действия помощника вне сессии.
